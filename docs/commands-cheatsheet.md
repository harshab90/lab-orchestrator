# lab-orchestrator — command cheat sheet

Quick reference for day-to-day use of the lab. Node names in this
topology: `seattle`, `raleigh`, `india`, `london` (PE routers),
`dallas`, `singapore` (P routers / Route Reflectors).

## Lifecycle

```bash
# From inside the lab-orchestrator folder:
make full           # render configs + start containers + wire all 91 links
make status          # check all 6 nodes are Up
make clean           # tear down everything (stop + remove containers)
make configs          # just re-render configs from the topology YAML (no restart)
make wire             # just re-run wiring (rarely needed standalone)
```

Switch topology file (e.g. back to the cEOS version):
```bash
make TOPO=topologies/global-pe-p-backbone-ceos.yaml full
```

## Logging into a device

```bash
docker exec -it seattle vtysh
docker exec -it raleigh vtysh
docker exec -it india vtysh
docker exec -it london vtysh
docker exec -it dallas vtysh
docker exec -it singapore vtysh
```

Exit back to your Mac's shell:
```
exit
```

## Useful show commands, once inside vtysh

```
show bgp summary
show bgp ipv4 labeled-unicast
show bgp ipv4 labeled-unicast neighbors <peer-ip> advertised-routes
show bgp ipv4 labeled-unicast neighbors <peer-ip> received-routes
show bgp neighbors <peer-ip>
show running-config
show interface brief
show ip route
```

Note: labeled-unicast is a non-default address family in FRR — most
`show bgp ...` commands need `ipv4 labeled-unicast` spelled out
explicitly, or FRR replies "No such neighbor or address family".

## Editing a config directly (temporary, not saved)

Inside vtysh:
```
configure terminal
router bgp 65000
 address-family ipv4 labeled-unicast
  neighbor 10.3.1.1 route-map SOMETHING in
 exit-address-family
end
write memory     # NOT recommended here — see note below
```
**Don't use `write memory`** in this lab — the container's
`/etc/frr/frr.conf` is a bind-mounted file generated by
`make configs`; running `write memory` overwrites it, but your
*next* `make full` will regenerate and overwrite it right back from
the topology YAML. Treat the generated config as the source of
truth, edit `configs/templates/*.j2` and re-run `make full` instead
of hand-editing inside a running container.

## Checking wiring / container health from your Mac shell (not inside a device)

```bash
docker ps -a                          # all container statuses
docker logs <node-name> --tail 50     # boot logs for one node
docker exec <node-name> ip link       # interfaces inside that container
```
